pdf-aligner blueprint

機能要件のマスターデータ。仕様の変更・機能の進捗があった場合は、必ずこのファイルに反映する。

概要

複数ページの PDF を読み込み、全ページを行方向に並べた 1 枚の画像にする。生成される画像はプレビューで確認でき、PNG としてダウンロードできる。処理はブラウザ内で完結する。

画面

画面は 1 枚。ツールバー、ステータス行、プレビュー領域の縦 3 段で構成する。表示言語は日本語。

┌──────────────────────────────────────────────────────────────────┐
│ [PDFを選択] 列数:[10]  [−] 100% [＋] [画面に合わせる]  [PNGをダウンロード] │  ツールバー
├──────────────────────────────────────────────────────────────────┤
│ 描画中 12/40 ページ / 縮小: 実際の倍率 1.6倍 (8,000×20,000 px)         │  ステータス行
├──────────────────────────────────────────────────────────────────┤
│                                                                  │
│                        プレビュー領域                              │
│              (未読み込み時は「PDFをここにドロップ」)                  │
│                                                                  │
└──────────────────────────────────────────────────────────────────┘

機能要件

F1 PDF の読み込み

  • 読み込める PDF は 1 ファイル。ファイル選択、またはプレビュー領域へのドラッグ&ドロップで渡す。
  • 別の PDF を渡すと、画像、列数、倍率、メッセージを含む全ての状態を置き換える。読み込みに失敗した場合、以前の PDF は破棄され、エラーだけが表示される。
  • 複数のファイルを同時に渡したときは、どれも読み込まず、エラーを表示する。このとき、表示中の PDF、画像、列数、倍率はそのまま残る。
  • 同じファイルを続けて選んでも、再度読み込む。
  • PDF かどうかは、拡張子ではなく、実際に読み込めるかどうかで判定する。
  • プレビュー領域の外に PDF をドロップしても、ブラウザがその PDF を開いて画面が遷移することはない。
  • ページ数とファイルサイズの上限は設けない。
  • パスワード付き PDF には対応しない(エラーを表示する)。

F2 レイアウト

  • 全ページを行方向に並べる(左から右、上から下)。1 行に並べるページ数は列数で決まる。例: 1 行に 5 ページなら、1 行目に 1〜5 ページ、2 行目に 6〜10 ページを置く。
  • 最後の行が列数に満たないときは、残りのセルを背景色のままにする。
  • セルの大きさは、全ページの最大の幅 × 最大の高さ。各ページは縮小せず、セルの中央に置く。
  • 背景は薄いグレー(不透明)。ページ間の隙間と画像の外周の余白は、同じ幅にする。幅は 1 倍換算で 16 px で、倍率に比例する。ページに枠線は付けない。
  • 各ページは、白の不透明で塗ってから描く。背景が透明な PDF でも、背景色は透けない。
  • ページの回転と表示範囲は PDF の指定に従う。セルの大きさは、回転後のページの大きさで計算する。
  • 計算式は「データの実例」に示す。

F3 出力サイズと自動縮小

  • 目標の倍率は 2 倍(PDF の 1 pt を 2 px にする)。倍率を選ぶ画面はない。
  • 2 倍で作った画像が Chrome の canvas の上限(辺と面積)を超えるときは、超えない最大の倍率まで自動で縮小する。
  • 縮小したときは、ステータス行に、実際の倍率と出力の画素数を表示する。
  • canvas の上限値は、実際の Chrome での実測に基づいて確定し、この項に追記する。

F4 列数

  • 数値入力。既定値は「10 と総ページ数の小さい方」。範囲は 1 から総ページ数まで。
  • 入力のたびに画像へ反映する。連続して入力したときは、短い待ち時間を置き、最後の値だけを反映する。
  • フォーカスを外したとき、範囲外の値は範囲内に丸め、小数は四捨五入した整数にする。空欄のときは直前の値に戻す。
  • PDF を読み込むまでは無効。

F5 プレビュー

  • 生成した画像を、そのまま表示する。ダウンロードされる画像と同一であり、プレビュー専用に別に描いたり、別の解像度で作ったりしない。
  • 拡大・縮小の操作: ＋ / − ボタン(1 回で 1.25 倍、または 1/1.25 倍)、Ctrl+ホイールとトラックパッドのピンチ(カーソル位置を中心に拡縮)、倍率の表示ボタン(押すと 100%)。
  • 移動の操作: ドラッグ、または通常のスクロール。
  • 倍率の 100% は、画像の 1 px が物理画面の 1 px に当たる状態。Retina などの高密度ディスプレイでも、画像のピクセルがそのまま見える。
  • 倍率の範囲は「10% と全体が収まる倍率の小さい方」から 800% まで。巨大な画像で、全体が収まる倍率が 10% を下回るときは、そこまで下げられる。
  • 倍率には 2 つのモードがある。
    • 画面に合わせる: 全体が領域に収まる倍率に自動で追従する。上限は 100%(小さい画像を拡大しない)。PDF の読み込み直後と、「画面に合わせる」を押したときに、このモードになる。ウィンドウの大きさ、列数、自動縮小による画像サイズが変わると、倍率を合わせ直す。
    • 固定: ユーザーが操作(＋ / −、Ctrl+ホイール、ピンチ)で決めた倍率を保つ。列数を変えても倍率は維持し、スクロール位置は左上に戻す。
  • PDF を読み込むまでは、操作は無効。

F6 ダウンロード

  • 形式は PNG(sRGB、不透明)。表示中の画像そのものを保存する。自動縮小したときは、縮小後の画像を保存する。
  • ファイル名は <元のファイル名(拡張子なし)>-<列数>cols.png。取り除く拡張子は、末尾の .pdf の 1 つだけ(大文字小文字は区別しない)。元のファイル名が拡張子だけ(空)のときは、aligned を使う。
  • 描画が完了した状態でのみ押せる。
  • 画像が大きすぎて PNG を生成できなかったときは、保存せずにメッセージを表示する。

F7 描画の進行・中断・失敗

  • 画像は、描きながらプレビューに順次表示する。ステータス行に「描画中 N/M ページ」を表示する。
  • 描画中に列数を変えたとき、または別の PDF を渡したときは、進行中の描画を中断し、新しい内容で最初から描き直す。
  • 一部のページの描画に失敗しても、他のページは描く。失敗したページのセルは背景色のままにし、画像には目印を描かない。ステータス行に、失敗したページ番号の警告を出し続ける。ダウンロードはできる。
  • フォントが埋め込まれていない PDF(日本語を含む)も、同梱のデータで描画できる。

F8 メッセージ一覧

ステータス行には、進捗、通知、警告、エラーの順に並べて表示する。エラーは、次の列数の変更、または別の PDF の選択で消える。

データの実例

レイアウトの計算式

入力: 各ページの幅 wi と高さ hi(pt。回転と表示範囲を反映)、ページ数 n、列数 c、倍率 s(目標は 2)。

セルの幅    cw = max(w_i) × s
セルの高さ  ch = max(h_i) × s
隙間・余白  g  = 16 × s
行数        r  = ceil(n / c)
画像の幅    W  = 2g + c×cw + (c−1)×g
画像の高さ  H  = 2g + r×ch + (r−1)×g

i 番目のページ(0 始まり)
  行 = floor(i / c)、列 = i mod c
  セルの左上   = ( g + 列×(cw+g),  g + 行×(ch+g) )
  ページの左上 = セルの左上 + ( (cw − w_i×s)/2,  (ch − h_i×s)/2 )

端数は、座標を四捨五入、画像の大きさを切り上げで整数にする。
自動縮小: g は s に比例するので、W と H も s に比例する。s=1 のときの大きさから、上限に収まる最大の s を求める。

例 2: A4 縦と A4 横を並べる、列数 2、倍率 2

最大の幅と高さはどちらも 842 pt なので、cw = ch = 1684、g = 32、r = 1。

  • 画像の大きさ: W = 64 + 2×1684 + 32 = 3464、H = 64 + 1684 = 1748 px。
  • 1 ページ目(縦、1190×1684 px): セルの左上 (32, 32)、横方向に 247 px ずらして、ページの左上は (279, 32)。
  • 2 ページ目(横、1684×1190 px): セルの左上 (1748, 32)、縦方向に 247 px ずらして、ページの左上は (1748, 279)。
  • 右端と下端の余白は、どちらも 32 px。

例 4: 倍率

  • プレビュー領域が 1000 × 800 px(CSS px)、画像が例 1 の 2476 × 5180 px、画面の密度が 1 のとき: 「画面に合わせる」の倍率は min(1000/2476, 800/5180, 1) ≈ 0.154 で、表示は 15%。倍率の範囲は 10%〜800%。
  • 画像が 1 ページだけ(1254 × 1748 px)で、領域が 2000 × 2000 px のとき: 「画面に合わせる」は上限の 100% で止まる。
  • 画面の密度(devicePixelRatio)が 2 のとき: 100% は CSS の拡大率 0.5、800% は CSS の拡大率 4。

例 6: 大きなページ数(自動縮小の対象になりうる例)

A4 を 150 ページ、列数 10。1 倍のとき cw = 595、ch = 842、g = 16、r = 15 なので W = 6126、H = 12886 px。2 倍にすると 12252 × 25772 px(約 3.16 億 px)。この大きさが canvas の上限を超えるときは、上限に収まる最大の倍率まで縮小する(上限値は F3 を参照)。

非機能要件

  1. 通信: 外部との通信を一切行わない。PDF の内容は、ブラウザの外へ送信されない。 pdf.js の付属アセット(CMap、標準フォント、wasm)も同一オリジンから配信し、外部の CDN は使わない。
  2. 対象ブラウザ: Google Chrome の最新安定版のみ。 Chrome 以外の判定や警告は行わない。
  3. 性能: 数値の目標値は設けない。 A4・30 ページと A4・150 ページの描画完了までの時間を計測し、実測を見てから目標値を決める。
  4. メモリ: 出力画像(canvas)の面積上限で、使用量を有界にする。 ページごとの描画結果のキャッシュは持たない。
  5. 描画中の応答性: 描画中も進捗の更新と操作を止めない。 描画中に列数を変更した場合、または別の PDF をアップロードした場合は、進行中の描画を中断して新しい操作を反映する。
